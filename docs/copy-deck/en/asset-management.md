## 02 — The problem it addresses

**Eyebrow:** 01 — THE PROBLEM

**Headline:** The data exists. It is in different places.

**Body:**
Most asset owners already hold a great deal of information. Test reports sit in folders. Oil results sit with the laboratory. Monitoring data sits in each vendor's system. Loading sits in SCADA. Age and cost sit in the finance system. Each is correct. None answers the question a planner actually has: of all my assets, which one first?

Without a common record, maintenance tends to follow the calendar and replacement tends to follow age. Both are reasonable defaults. Both spend effort on assets that did not need it and miss some that did.

**Pull-quote:**
The risk is not a lack of data. It is effort placed on the wrong assets.

## 04 — How to read the result

**Eyebrow:** 03 — READING IT

**Body blocks**

- **Condition is one axis.** A health indication summarises what the tests and monitors say about an asset. It is a calculated summary, not a measured quantity, and it is only as good as its inputs and its rules.
- **Importance is the other.** A transformer in poor condition feeding a redundant, lightly loaded bay is a different problem from the same transformer on a single supply route. Ranking needs both axes.
- **The rules should be visible.** A ranking is useful when an engineer can open it and see which results produced it. A score with no trace back to the data should not drive an investment.
- **Gaps are findings too.** An asset with no recent data is not a healthy asset. It is an unknown one. A good record shows that plainly.

**What it can and cannot tell you (honesty block)**

| It can tell you | It cannot tell you |
|---|---|
| Which assets the available data says to look at first | Anything about an asset for which no data has been entered |
| How one asset compares with others of its kind | The true condition of an asset better than the underlying tests can |
| Where test and monitoring coverage is missing | What to decide. It supports a decision; the engineer and the organisation make it |
| How maintenance and investment plans change when the data changes | That a plan will be carried out; that is a matter of process and budget |

**Glossary one-liners**
- **APM** — asset performance management: using condition and performance data to plan maintenance and investment.
- **Health indication (health index)** — a calculated summary of an asset's condition from several data sources.
- **Criticality** — how much the network or the operation depends on an asset.
- **Condition-based maintenance** — work triggered by the measured state of the asset.
- **GIS** — in asset management software this often means geographic information system. Elsewhere on this site it means gas-insulated switchgear.

## 07 — How a project usually starts

**Eyebrow:** 06 — WHERE TO START

**Headline:** Start with the data you already have.

1. **List the assets.** One agreed register, with one identity per asset.
2. **List the data.** Which tests, samples and monitors exist for each asset class, and where the results are kept.
3. **Agree the rules.** How condition is assessed for each asset class, in terms your engineers recognise.
4. **Load, check, correct.** The first ranking is a test of the data as much as of the fleet.
5. **Use it in the plan.** The result goes into the maintenance and investment cycle, and the plan's outcome goes back into the record.

**Caption:** General sequence, for orientation. The actual project scope is defined per organisation.

## 10 — FAQ

**Q: Is this a monitoring system?**
No. It is software. It uses the results of testing and monitoring and adds no measurement of its own.

**Q: Is "Megger APM" the product name?**
No. The product is IPS®APM, from IPS-ENERGY, offered by Megger.

**Q: Do we need online monitors before we can use it?**
No. Offline test results and operating history are data too. Monitoring adds continuity to the record where it is installed.

**Q: Which of our existing systems can it connect to?**
That is defined for each organisation. Tell us what you run and the question goes to the manufacturer with the right detail.

**Q: Will the software tell us which transformer to replace?**
It will rank assets from the data and the rules you agree. The decision remains with your engineers and your organisation.
